# تأمين قاعدة البيانات — المرحلة 2 (عزل الشركات والموظفين)

**المتطلب:** تنفيذ المرحلة 1 أولاً. كل شيء هنا يُشغَّل يدوياً من Supabase → SQL Editor.

## ما المشكلة التي تحلها؟
بعد المرحلة 1 صار الوصول للمسجّلين فقط، لكن أي شركة أو موظف مسجَّل كان ما يزال يستطيع —
عبر المفتاح العام وبدون استخدام التطبيق— قراءة وتعديل بيانات **كل** الشركات والموظفين.
هذا السكربت يفرض داخل قاعدة البيانات نفس قواعد الرؤية التي يطبّقها التطبيق في الواجهة:

| الدور | ما يراه | ما يكتبه |
|---|---|---|
| موظف نظام (أي دور غير الشركة والموظف) | كل شيء كما هو الآن | كما هو الآن |
| مسؤول شركة | شركاته، موظفو شركاته (الربط الحالي + الأرشيف)، مهامها وحضورها وفواتيرها وتحصيلها وتذاكرها، وحسابات موظفيه | مهام شركته، حضور موظفيه، تعديل موظفيه، تذاكره |
| موظف | سجله، مهامه، حضوره، روابطه وتحصيله ورواتبه، شركاته المرتبط بها، تذاكره | تحديث مهامه، تعديل سجله (دون تغيير ربط الحساب)، رفع مستندات مهامه، تذاكره |

الفواتير والروابط والتحصيل والرواتب والقائمة السوداء والمسميات الوظيفية: **كتابتها لموظفي النظام فقط**.
المستخدمون (`users`): الشركة والموظف يريان صفّهما فقط (والشركة أيضاً حسابات موظفي شركاتها).

## الملفات
| الملف | الغرض |
|---|---|
| `10_phase2_preflight.sql` | فحص الأعمدة والمستخدمين قبل التنفيذ (قراءة فقط) |
| `11_phase2_isolation.sql` | التطبيق (معاملة واحدة، يمكن إعادة تشغيله؛ يتوقف برسالة واضحة إن غاب عمود مطلوب) |
| `19_rollback_phase2.sql` | تراجع كامل إلى نهاية المرحلة 1 |

## الترتيب
1. خذ نسخة احتياطية.
2. شغّل `10_phase2_preflight.sql`:
   - الجدول الأول: كل الصفوف يجب أن تكون `present = true`. إن ظهر `false` فأرسله لي قبل المتابعة.
   - الجدول الثالث: مستخدمو شركات بلا شركة أو موظفون بلا سجل موظف — سيرون بيانات فارغة بعد التطبيق؛ اربطهم أو تجاهلهم إن كانوا حسابات قديمة غير مستخدمة.
3. شغّل `11_phase2_isolation.sql`.
4. اختبر بحسابات حقيقية (نافذة خاصة لكل حساب):
   - **مسؤول شركة**: لوحة التحكم، الموظفون، المهام (وتفاصيل مهمة ومستنداتها)، الحضور، الفواتير، التقارير المتاحة له، تذكرة دعم.
   - **موظف**: لوحة التحكم، المهام وتحديث حالتها، الحضور، التحصيل، تعديل ملفه، تذكرة دعم.
   - **مدير/مسؤول**: افتح كل الشاشات (موظفون، شركات، ربط، فواتير، تحصيل، حضور، تقارير، مستخدمون) وتأكد أن كل شيء يعمل كالسابق.
5. إن ظهرت شاشة فارغة أو خطأ «violates row-level security»: شغّل `19_rollback_phase2.sql` وأرسل لي اسم الشاشة والدور.

## ملاحظات
- شركة تحتفظ برؤية الموظفين الذين انتهى ربطهم بها (من الأرشيف) وحضورهم، كما كان يعمل التطبيق تماماً.
- موظفو النظام ذوو الأدوار المخصّصة ما زالت صلاحياتهم الدقيقة (لكل شاشة) تُفرض من الواجهة فقط؛ فرضها على قاعدة البيانات هو المرحلة 2ب إن أردتها.
- تنظيف النصوص في الواجهة (XSS) هو المرحلة 3.
