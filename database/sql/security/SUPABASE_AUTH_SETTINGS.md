# إعدادات Supabase للحماية من تخمين كلمات المرور (من لوحة التحكم — بلا كود)

المصدر: توثيق Supabase (صفحتا Password security وRate limits). الأسماء والمسارات قد تتغير قليلاً بين الإصدارات.

## 1) طول كلمة المرور وقوّتها
**Authentication → Sign In / Providers → Email** (أو: Authentication → Providers → Email)

| الإعداد | القيمة المقترحة | ملاحظة |
|---|---|---|
| Minimum password length | **10** (أو 12) | توصي Supabase بألا تقل عن 8 |
| Password requirements | **حروف صغيرة + كبيرة + أرقام + رموز** (الخيار الأقوى) | توصي به Supabase |
| Prevent use of leaked passwords | **ON** | يفحص كلمات المرور المسرّبة (HaveIBeenPwned). **يتطلب خطة Pro فما فوق** |

- كلمات المرور المؤقتة التي يولّدها التطبيق (12 خانة بحروف كبيرة وصغيرة وأرقام ورموز) **تتوافق** مع الخيار الأقوى.
- المستخدمون الحاليون بكلمات ضعيفة يستطيعون الدخول؛ تُطبَّق القواعد عند تغيير كلمة المرور فقط. للإجبار: اطلب منهم تغييرها، أو من المسؤول تعيين كلمة جديدة.
- التطبيق يتحقق حالياً من **8 أحرف** كحد أدنى في شاشات التسجيل وتغيير/استعادة كلمة المرور وإضافة مستخدم. إن رفعت الحد في Supabase إلى 10+ فأخبرني لأحدّث الرسائل والتحقق في الواجهة كي تتطابق مع القاعدة.

## 2) حدود المعدّل (منع التخمين الآلي)
**Authentication → Rate Limits**

الحدود الافتراضية حسب التوثيق:
- تسجيل الدخول بكلمة المرور وتجديد الجلسة (`/auth/v1/token`): **150 طلباً لكل 5 دقائق لكل عنوان IP** (قابل للتعديل).
- التسجيل/الاستعادة/إعادة الإرسال/OTP: **30 طلباً لكل 5 دقائق لكل IP** (قابل للتعديل).
- التحقق (`/verify`): 30 لكل 5 دقائق لكل IP.
- تجاوز الحد يُرجع HTTP 429.

الموصى به لمشروعك:
- خفّض حد **Token (sign-in)** من 150 إلى ما بين **30 و60** لكل 5 دقائق لكل IP (مكاتب كثيرة خلف IP واحد: لا تُفرط).
- أبقِ حدّ التسجيل/الاستعادة عند **30** أو أقل.
- إن كان لديك مزوّد بريد SMTP مخصّص فاضبط حدّ الرسائل بالساعة بما يناسب حجمك.

## 3) CAPTCHA (حماية إضافية ضد الأتمتة)
**Authentication → Attack Protection** (أو Bot and Abuse Protection): فعّل CAPTCHA (hCaptcha أو Cloudflare Turnstile).
⚠️ بعد التفعيل يجب إضافة مكوّن CAPTCHA في صفحات الدخول والتسجيل واستعادة كلمة المرور وتمرير الرمز (`captchaToken`) مع كل طلب، وإلا ستفشل
كل عمليات الدخول. أخبرني إن أردت تنفيذ هذا الجزء في الكود (Turnstile مجاني). لا تفعّله من اللوحة قبل ذلك.

## 4) إجراءات مساعدة
- **Confirm email**: إن كان الإنشاء الذاتي للموظفين يعمل لديك بجلسة فورية فهذا الخيار مغلق؛ لا تغيّره دون إخباري (سيؤثر على تسجيل الموظفين الذاتي).
- **Sessions**: Authentication → Sessions: يمكنك ضبط مدة قصوى للجلسة (Time-box) أو الخمول (Inactivity timeout) — اختياري (بعض الميزات تتطلب Pro).
- بعد تنفيذ المرحلة 1: لتسجيل خروج كل الجلسات القديمة مرة واحدة (اختياري)، غيّر JWT secret أو استخدم «Sign out all users» إن توفّر خيارها في مشروعك — **سيُخرج الجميع**، فاختر وقتاً مناسباً.
